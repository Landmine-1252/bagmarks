# Validation and in-game checklist

## Automated verification

From the repository root:

```sh
make test
make package
```

Use `LUA=/path/to/lua5.1 LUAC=/path/to/luac5.1` if needed. A different Lua language version is not a substitute for the syntax check. Python 3 is required; Pillow is required only to regenerate the included original icons.

Run `make package` from the repository root to validate the addon and create `dist/BagMarks-<version>.zip`. The standalone `python3 tools/package.py` command reads the version from `BagMarks.toc` and validates the finished archive. See the [build and upload instructions](PACKAGING.md).

For a new version, update `## Version` in `BagMarks.toc` and `A.version` in `Core.lua` to the same value, add an entry to `CHANGELOG.md`, and run `make package`. The README is a player guide and needs no version update. The in-game version labels use `A.version`. For a patch release, increment the final number, for example `1.0.0` to `1.0.1`. Packaging does not increment the version automatically. Each version gets its own ZIP filename in `dist/`.

Mail routing regressions exercise the Comprehension scroll IDs, ordinary power-up scrolls, exact item exceptions, short display names after character switches and the stored addresses used for attachment checks. Combat cases exercise the configured mouse shortcut, foreground slots, pooled buttons, typing focus and merged stack selection.

**Automated validation does not include an in-game test run.** In particular, mocks do not validate native input routing, secure execution, rendering, real network timing, or true GUID lifecycle. Collector regressions reproduce Ellesmere's inspected API interactions, rather than claiming an end-to-end test of Ellesmere in the client.

## Client preparation

1. Use Forever 1.60.1, starting with default Blizzard bags and no other addons. Record the version/build from `/dump GetBuildInfo()`.
2. Install the packaged `BagMarks` folder and restart the client. Confirm it appears in the AddOns list.
3. Enable errors with `/console scriptErrors 1`. For the taint pass, use `/console taintLog 1`, restart or reload, reproduce the interactions, and inspect the client's `Logs/taint.log` if produced. Restore the previous logging setting afterwards.
4. Use expendable items: at least two identical nonstackable copies, stackable trade goods, poor-quality vendor items, a bound item, and a normal mailable item. Do not use valuable gear for destructive tests.

## Protection acceptance cases

Every case below needs a real Forever test. Use expendable items and compare results with only BagMarks enabled first.

- [ ] **Hold and release:** Mark gear and a consumable Locked. Outside merchant/mail/trade/auction and item-targeting contexts, neither should acquire a BagMarks native hold. Equip, use, pick up, move, and bank them normally. Open each destructive/transfer context and inspect `C_Item.IsLocked`: holds should engage on the exact GUID, then release after every context closes. Clear marks, disable, logout, and repeat. A bank window alone must not create holds.
- [ ] **Ordinary use and equipping:** Keep Cozy Sleeping Bag, Hearthstone, weapons, armor, and an expendable potion Locked. Verify normal use, cooldowns, right-click equip, dragged equip, unequip, and native `/use` bindings outside transfer windows. Consumable use should consume the item normally. Test Blizzard and Ellesmere bags, reload/relog while equipped, and confirm GUID marks when returned to inventory. Turn marking mode off when testing ordinary clicks.
- [ ] **Transfer protection boundaries:** With Locked gear and reusable items, open merchant, mail, trade, and auction windows in turn; holds should engage immediately and prevent sales/attachments/offers/posting where honored. Item targeting remains guarded, including Disenchant. Closing all risks should permit equip/use again, including during combat when the native action itself is allowed. Banking and ordinary cursor pickup must not return or hold an item. Test equipped items and overlapping contexts.
- [ ] **Consumables and metadata independence:** Use expendable Locked potions/food and verify intentional use consumes them. Missing use-spell data and diagnostic consumable classification must not block ordinary use or equipping. Test an uncached gear item after login. During merchant/mail/trade/auction or known item targeting, the Locked mark must still request a hold without requiring metadata.
- [ ] **Destroy/drop fallback:** Pick up expendable Locked gear outside transfer windows; it must stay on the cursor so dragging to equipment works. Drop it into the world or request destruction. `DELETE_ITEM_CONFIRM` should synchronously return the exact cursor item and dismiss the normal mouse confirmation. Compare Normal/Junk/Mail and quality/quest variants, and record missing-event/noncursor/gamepad limitations. Do not treat these unsupported paths as guaranteed protection.
- [ ] **Gamepad and direct deletion:** With gamepad UI active, check whether native holds block deletion and whether any confirmation survives cursor return. Cancel any surviving confirmation manually. Treat noncursor/direct deletion as an explicit API limit, not a passed protection case. Never test on valuable gear.
- [ ] **Player trade:** Use a second player. Try right click, drag, modified-click, and any installed trade helper with a Locked item. If one reaches an outgoing slot, BagMarks should request trade cancellation. Repeat for the enchant slot, acceptance changes, and a preexisting offer when BagMarks is enabled. A Normal identical copy must trade normally. Verify cancellation and item return on both clients; do not infer them from the chat message alone.

## Copyable diagnostics

Run `/bm debug` or `/bmcheck`, click **Select all**, and press **Ctrl+C**. The report includes the addon/client versions, marking controls, interaction flags, the live mailbox state, and readable marked items. `/bm debug 211527` focuses on Cozy Sleeping Bag; any positive item ID can be used. Filtering only selects report entries and never changes how marks are stored.

Reports are explicit snapshots. **Refresh** collects another one. They include at most 40 matching slots and disclose that limit. Closed-bank items are not scanned, and inventory details pause during combat. Character names, recipients, raw GUIDs, and the full SavedVariables database are omitted. Collecting a report does not refresh protection, unlock anything, or send items. When sharing one, include what happened and whether the item was still grey at capture time.
