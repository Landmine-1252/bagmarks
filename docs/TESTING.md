# Validation and in-game checklist

## Automated verification

From the repository root:

```sh
make test
make package
```

Use `LUA=/path/to/lua5.1 LUAC=/path/to/luac5.1` if needed. A different Lua language version is not a substitute for the syntax check. Python 3 is required; Pillow is required only to regenerate the included original icons.

The build entry point is `Makefile`. Run `make package` from the repository root to validate the addon and create `dist/BagMarks-<version>.zip`. `python3 tools/package.py` skips the Lua checks and regression suites but still validates the finished archive; it reads the version from `BagMarks.toc`. See [build and upload instructions](PACKAGING.md) for the 1.0.3 package and CurseForge submission details.

For a new version, update `## Version` in `BagMarks.toc` and `A.version` in `Core.lua` to the same value, add an entry to `CHANGELOG.md`, and run `make package`. The README is a player guide and needs no version update. The in-game version labels use `A.version`. For a patch release, increment the final number, for example `1.0.0` to `1.0.1`. Packaging does not increment the version automatically. Each version gets its own ZIP filename in `dist/`.

Version 1.0.3 passed **235 mocked regression tests under Lua 5.1** and **67 Python tests** (10 archive tests, 14 release-metadata tests, 19 release-tag/source tests, and 24 publishing tests), plus static checks and validation of `dist/BagMarks-1.0.3.zip`. Version 1.0.2 passed 205 Lua tests, and version 1.0.1 passed 185. The 1.0.3 archive is ready for local installation and the in-game checks below; it has not been committed, tagged, or published by this build.

The full-size mark option adds **10 Lua regression cases** in 1.0.3. They cover saved/default/corrupt size preferences, bag and bank geometry, display layers, theme colors and opacity, Ellesmere icon-column visibility, combined-stack identity, and deferred combat layout. Tests model anchors and layer choices; they do not render the client UI. The earlier 1.0.2 ZIP is unchanged.

Another **20 Lua cases** cover delayed reusable metadata, mailbox state reconciliation, and diagnostics. The stale-mailbox regression fails with the old lifecycle code: BagMarks retains `mailOpen=true` and an owned sleeping-bag hold after the client reports that mailing has ended. The repaired path covers missing close events, modern hide notifications, deferred state updates, reopening, active-but-hidden UI, unknown/secret/missing APIs, overlapping risks, combat, unsent marks, and pending recipient work. Reports are checked for read-only behavior, independent copies, filtering, private-field omission, typing focus, and bounded output.

Lua tests load every addon Lua file in TOC order, dispatch the addon lifecycle, and exercise state, UI models, and asynchronous queues. Static checks cover every Lua file, manifest completeness, SavedVariables declarations, version consistency, AddOns compartment callbacks, both unbound XML actions, texture dimensions and alpha, and prohibited destructive/global-replacement calls. The mock intentionally throws if the addon attempts to send mail, destroy an item, or automatically sell/attach a nonmatching state. The hover tests cover live GUID targeting, foreground focus, Blizzard/Ellesmere bags and banks, combined stacks, review flags, independent binding history, existing Jump/override bindings, selected-tab state, pointer scaling, and mode cleanup. Native input delivery, key repetition, visual layout, and taint require the client checks below.

Version 1.0.3 adds an optional full-size mark under Appearance, reusable-item recovery from stale mailbox state, and copyable diagnostics. Small corner remains the default. Version 1.0.2 added the hover shortcut, native settings tabs, clearer mode status, and pointer badge. New profiles and resets use Ctrl + Shift + Right Click; saved shortcuts remain unchanged. Version 1.0.1 added combat icon fixes and put Locked first in the mark cycle. The original reusable-item classification and archive changes shipped in the initial 1.0.0 code. SavedVariables still use schema 2, preserving existing preferences and marks. CurseForge acceptance remains unverified. Earlier development numbers through 1.1.4 remain recorded in the [development history](DEVELOPMENT_HISTORY.md).

Archive tests cover an extracted single-folder installation, exact source bytes, reproducible output, explicit directory records, standard file-type metadata, missing TOC dependencies, repository wrappers, duplicate paths, symlinks, unsafe paths, truncated ZIPs, and preserving the previous archive when packaging fails. These are local release-format checks, not an implementation of CurseForge's private verifier. The completed ZIP also receives checksum and manifest validation during every package build.

Release tests cover exact tag/version matching, rejection of unsupported tag formats, TOC/Core consistency, a README independent of release numbers, missing/empty/duplicate changelog sections, selecting only the requested release, versioned documentation links, and refusing to write publication metadata when validation fails. Mocked GitHub API tests also check creating a missing tag at the tested commit, existing lightweight and annotated tags, selecting the original tag when `main` advances, mismatched commits, similar tag names, failed requests, malformed data, and refusing to move or recreate pushed tags.

Publishing tests reproduce a release created in the GitHub web UI before its addon ZIP is attached. They also cover new releases, interrupted drafts, repeated runs, matching and conflicting assets, digest verification with a download fallback, immutable releases, pagination, failed uploads, mismatched archive versions, and preserving existing titles and notes. These tests make no network writes. The workflow was linted locally with `actionlint`. Automatic runs start only on version-tag pushes, with manual releases and retries also available. Ordinary commits and pull requests do not start a run. Builds use read permissions; publishing receives write permissions only after the checks pass.

The revised publisher still requires a successful hosted run; offline tests do not establish GitHub's write permissions or live upload behavior.

**Automated validation does not include an in-game test run.** In particular, mocks do not validate native input routing, secure execution, rendering, real network timing, or true GUID lifecycle. Collector regressions reproduce Ellesmere's inspected API interactions, rather than claiming an end-to-end test of Ellesmere in the client.

## Client preparation

1. Use Forever 1.60.1, starting with default Blizzard bags and no other addons. Record the version/build from `/dump GetBuildInfo()`.
2. Install the packaged `BagMarks` folder and restart the client. Confirm it appears in the AddOns list.
3. Enable errors with `/console scriptErrors 1`. For the taint pass, use `/console taintLog 1`, restart or reload, reproduce the interactions, and inspect the client's `Logs/taint.log` if produced. Restore the previous logging setting afterwards.
4. Use expendable items: at least two identical nonstackable copies, stackable trade goods, poor-quality vendor items, a bound item, and a normal mailable item. Do not use valuable gear for destructive tests.

## Copyable diagnostics

Run `/bm debug` or `/bmcheck`, click **Select all**, and press **Ctrl+C**. The report includes the addon/client versions, marking controls, interaction flags, the live mailbox state, and readable marked items. `/bm debug 211527` focuses on Cozy Sleeping Bag; any positive item ID can be used. Filtering only selects report entries and never changes how marks are stored.

Reports are explicit snapshots. **Refresh** collects another one. They include at most 40 matching slots and disclose that limit. Closed-bank items are not scanned, and inventory details pause during combat. Character names, recipients, raw GUIDs, and the full SavedVariables database are omitted. Collecting a report does not refresh protection, unlock anything, or send items. When sharing one, include what happened and whether the item was still grey at capture time.
